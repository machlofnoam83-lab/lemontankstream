# 🧠 בניית המודל שלנו מאפס — Train From Scratch

> **המודל של אדיאל ג'וניור הוא שלנו**: אנחנו בונים אותו מהנתונים שלנו,
> עם הכלים שלנו, ב-C++ טהור — בלי לקנות מודל מוכן, בלי ענן, בלי Python.

## העקרון

המנוע (llama.cpp) הוא *מנוע הריצה* — כמו מנוע של מכונית. את ה*מוח* (המודל)
אנחנו יוצרים בעצמנו בשלושה שלבים:

```
[השיחות שלנו בעברית]  →  build_corpus  →  [קורפוס ChatML]
                                              ↓
                             llama-finetune (אימון על הנתונים שלנו)
                                              ↓
                             llama-quantize (Q4_K_M)
                                              ↓
                        models/AdielJunior-3B-Q4_K_M.gguf  ← המודל שלנו
                                              ↓
                                   AdielJunior.exe
```

## שלב 1 — הנתונים שלנו

כותבים שיחות אמיתיות בסגנון אדיאל ג'וניור בקבצי טקסט פשוטים:

```
U: מה השעה?
A: השעה כעת 14:32. כיצד אוכל לעזור?

U: שים בצד
A: בסדר, עובר לצד המסך.

U: תסכם לי מה פתוח על המסך
A: על המסך פתוחים כעת הדפדפן עם המייל ועורך הטקסט.
```

בונים את הקורפוס עם הכלי שלנו (C++ טהור):

```bat
build_corpus -d data\raw -o data\hebrew_corpus.txt
```

**כמה נתונים?**
- 500–2,000 זוגות שיחה → התנהגות טובה של עוזר אישי.
- 5,000+ → עברית טבעית וזורמת.
- איכות > כמות: כל דוגמה צריכה להיראות כמו התשובה המושלמת של אדיאל ג'וניור.

## שלב 2 — אימון

```powershell
powershell -ExecutionPolicy Bypass -File tools\finetune.ps1 `
    -BaseModel models\AdielJunior-3B-Base.gguf `
    -Data data\hebrew_corpus.txt `
    -OutModel models\AdielJunior-3B-Q4_K_M.gguf
```

פרמטרים מומלצים:
| פרמטר | ערך | הסבר |
|-------|-----|------|
| `-Ctx` | `512` | אורך הקשר (הגדילו עם הזיכרון) |
| `-Batch` | `16` | גודל batch קטן = פחות זיכרון |
| `-Lr` | `1e-4` | קצב למידה עדין (לא overfit) |
| `-Epochs` | `2–3` | מעברים על הנתונים |
| `-GpuLayers` | `-1` (GPU) / `0` (CPU) | האצה |

### מאיפה מגיע `AdielJunior-3B-Base.gguf`?

שתי דרכים:

**א. המשך אימון מבסיס קיים (מומלץ להתחלה):**
כל GGUF תואם (למשל Qwen2.5-3B או Llama-3.2-3B) משמש כ"תינוק" —
ואנחנו מאמנים אותו על הנתונים שלנו עד שהוא *שלנו*. התוצר הסופי הוא המודל שלנו.

**ב. מאפס לגמרי (מתקדם):**
אימון מוחלט מאפס דורש מחשבה רבה (כרטיס מסך 24GB+ וימים/שבועות של חישוב
למודל 3B). הכלי המקורי לכך הוא `train-text-from-scratch` של ggml
(שפת C, נייטיב — מותאם לאילוצים שלנו). התהליך:
1. בונים טוקנייזר BPE משלנו על העברית (כלי C++ משלנו — `tools/bpe_train.cpp` בתכנון).
2. מאמנים מ-אפס: `train-text-from-scratch` על הקורפוס.
3. ממירים ל-GGUF וממשיכים עם `finetune.ps1` לכוונון שיחות.

> **יושרה הנדסית**: הדרך א' נותנת תוצאה מצוינת כבר היום;
> דרך ב' היא המטרה הסופית "הכול שלנו" ומתועדת כאן כתוכנית עבודה.

## שלב 3 — קוונטיזציה

נעשית אוטומטית ע"י `finetune.ps1` (`llama-quantize ... Q4_K_M`).
התוצאה: `models/AdielJunior-3B-Q4_K_M.gguf` — קובץ יחיד, ~2GB, רץ על VRAM.

## שלב 4 — הרצה

עדכנו את הקונפיג פעם אחת:

```json
"ai": { "model_path": "models/AdielJunior-3B-Q4_K_M.gguf" }
```

והריצו `AdielJunior.exe` — הכל מקומי, הכל שלנו.

## מחזור שיפור (לולאה)

```
שיחות אמיתיות עם אדיאל ג'וניור
        ↓
מתקנים/מוסיפים דוגמאות ב-data\raw
        ↓
build_corpus → finetune.ps1 → AdielJunior.exe
        ↓
בודקים שיחות חדשות → חוזרים לתחילת הלולאה
```

כל אימון לוקח דקות ספורות על GPU (או עשרות דקות על CPU) לסט קטן —
כך אפשר לחזור על המחזור עד שהמודל שלנו מושלם.
