# 🛡️ אבטחת LemonTank Stream

> המסמך הזה מתאר את שכבת האבטחה של המערכת: מה היא עושה, איך מנהלים אותה,
> ואיפה הגבולות שלה. הקובץ הזה הוא גם ה"חוזה" — מה שכתוב כאן אמור להתאים לקוד.

---

## 1. הרעיון: דלת אחת בלבד

```
        האינטרנט
            │
            ▼
   ┌──────────────────────────────────────────────┐
   │  server.mjs — שער האבטחה (פורט 3000)         │
   │  • ניקוי כותרות וזיהוי IP אמיתי              │
   │  • זיהוי תקיפות (SQLi/XSS/RCE/traversal…)    │
   │  • חסימת כלי יירוט (Burp/ZAP), סורקים, TOR   │
   │  • מלכודות, הגבלת קצב, חסימת IP אוטומטית     │
   └──────────────────────────────────────────────┘
            │  (רק בקשות נקיות, עם חתימת HMAC)
            ▼
   ┌──────────────────────────────────────────────┐
   │  Next.js — בתוך אותו תהליך                    │
   │  • אימות הרשאות (RBAC) בכל נקודת קצה          │
   │  • Zod על כל קלט · parameter binding בכל SQL  │
   │  • CSRF, CSP עם nonce, סשנים חתומים           │
   │  • סריקת גוף הבקשה + חסימת IP גם כאן          │
   └──────────────────────────────────────────────┘
            │
            ▼
      SQLite (WAL) — קובץ מקומי, לא חשוף לאינטרנט
```

**למה זה חשוב:** אין פורט נוסף שאליו אפשר לפנות ישירות. גם אם מישהו ינסה
`http://server:3311` — אין מה לפנות אליו. כל בקשה, דף, API או קובץ מדיה עוברת בשער.

## 2. מה נחסם, ומתי

| מה זוהה | דוגמה | תגובה |
|---|---|---|
| הזרקת SQL | `?q=1 UNION SELECT password FROM users` | 🚫 חסימה + **חסימת IP ל-2 שעות** |
| הרצת פקודות | `;cat /etc/passwd`, `${jndi:ldap://…}` | 🚫 חסימה + **12 שעות** |
| חדירת נתיבים | `../../../../etc/passwd` | 🚫 חסימה + **6 שעות** |
| XSS | `<script>`, `onerror=`, `javascript:` | 🚫 חסימה + **שעה** |
| כלי יירוט | כותרת `Proxy-Connection`, חתימת Burp/ZAP | 🚫 חסימה + **3 שעות** |
| סורקי פגיעויות | `sqlmap`, `nikto`, `nuclei`, `gobuster` | 🚫 חסימה + **3 שעות** |
| נתיבי מלכודת | `/.env`, `/wp-login.php`, `/phpmyadmin`, `/.git` | 🚫 חסימה + **24 שעות** |
| סריקת נתיבים | 40 בקשות ל-404 בחמש דקות | 🚫 חסימה + **12 שעות** |
| כוח גס | 20 כשלי התחברות ב-15 דקות | 🚫 חסימה + **שעה** |
| הברחת בקשות | `Content-Length` + `Transfer-Encoding` יחד | 🚫 חסימה + **שעה** |
| הצפה | מעל 600 בקשות בדקה | 429, ואחרי 3 חריגות — **חסימה** |
| זיוף Host / כותרות IP | `X-Originating-IP`, Host לא מורשה | 🚫 חסימה או ניקוד |

**החמרה אוטומטית:** כל חזרה של אותה כתובת **מכפילה** את זמן החסימה (עד 30 יום).

**מה לא נחסם סתם:** גלישה רגילה, חיפוש בעברית, גרש בתקציר ("rock'n'roll"),
משתמשים מאחורי VPN (ברירת מחדל: ניקוד בלבד — ראו §6),
וכתובות פנימיות (localhost/LAN) שלעולם לא נחסמות — כדי שלא תנעל את עצמך בחוץ.

## 3. איך לא נועלים את עצמך בחוץ

1. **פטור פנימי** — כתובות `127.0.0.1`, `10.x`, `192.168.x`, `172.16-31.x` לא נחסמות לעולם
   (אפשר לכבות: `node scripts/security.mjs set internal_bypass off`).
2. **חסינות אנשי צוות** — בקשה עם סשן של מנהל/עורך לא נחסמת, גם אם יצאה מכתובת חסומה.
3. **שחרור מהטרמינל:**
   ```bash
   node scripts/security.mjs bans              # מי חסום ולמה
   node scripts/security.mjs unban 1.2.3.4     # שחרור כתובת
   node scripts/security.mjs unban --all       # מנעול חירום — משחרר הכול
   node scripts/security.mjs mode monitor      # מצב ניטור: לוגים בלי חסימות
   ```
4. **מצב ניטור** — לפני עלייה לאוויר אפשר להריץ שבוע ב-`monitor` ולראות
   מה היה נחסם, בלי לחסום בפועל.

## 4. ניהול מהפאנל

`/admin/security` → **מרכז הבקרה של האבטחה**:

* מצב אכיפה / ניטור, מתג לכל מדיניות, ורשימת חסימות פעילות עם שחרור בקליק.
* רשימת התוקפנים הבולטים וַיומן אירועים חי.
* חסימה ידנית של כתובת (24 שעות כברירת מחדל), וניקוי חסימות ישנות.

הרשאה: צפייה — `security.read` (מנהל). שינוי מדיניות — `security.manage` (בעלים בלבד).

## 6. מדיניות פרוקסי / VPN / TOR

| ערך | משמעות |
|---|---|
| `off` | לא לחסום — רק לתעד |
| `score` *(ברירת מחדל)* | ניקוד בלבד. פרוקסי אמיתי מתנהג כמו דפדפן ולכן לא נחסם, אבל כל סימן נוסף מצטבר |
| `block-writes` | גלישה מותרת, אבל התחברות/הרשמה/העלאה נחסמות (מומלץ אם יש ספאם) |
| `block-all` | חסימת כל תנועה מפרוקסי/ענן/TOR |

**TOR** חסום כברירת מחדל (`TOR_BAN=on`) — פנייה מיציאת TOR נחסמת ל-24 שעות.

**למה לא לחסום VPN כברירת מחדל?** כי גם לקוחות תמימים משתמשים ב-VPN,
וחיפוש שקט של כתובת שהיא "מרכז נתונים" עלול לחסום אנשים אמיתיים.
מעבירים ל-`block-writes` או `block-all` בשורה אחת — מהפאנל או מהטרמינל:
`node scripts/security.mjs set proxy_policy block-all`.

## 7. הסתרת זהות השרת ("לאתר מי ה-host")

| שכבה | מה נעשה |
|---|---|
| כותרות | אין `Server`, אין `X-Powered-By`, אין גרסאות |
| שגיאות | הודעות גנריות בעברית; פרטים נכתבים ללוג בשרת בלבד |
| נתיבי מערכת | `/data/`, `/scripts/`, `/security/`, `/server.mjs`, `/package.json` → 403 + חסימה |
| קבצי DB | מסד הנתונים לא נמצא בשום נתיב סטטי שנגיש מהאינטרנט |
| מקורות | כל סקריפט מותאם לסביבה — אין תלויות npm עם גישה לרשת בשרת |
| אימות Host | הגדר `ALLOWED_HOSTS` — כל בקשה ל-Host אחר נחסמת (421) |

בנוסף, מומלץ להסתיר את כתובת ה-IP האמיתית מאחורי **Cloudflare** (Proxy ON) — ראו `deploy/nginx-security.conf`.

## 8. הרצה בפרודקשן — צ'קליסט

```bash
# 1) סודות חזקים — פעם אחת
node scripts/gen-secrets.mjs --write

# 2) מצב פרודקשן
```

| נושא | חובה |
|---|---|
| HTTPS | חובה. HSTS מוזרק אוטומטית מאחורי HTTPS |
| חומת אש | `ufw default deny incoming && ufw allow 22,80,443/tcp` |
| Fail2ban | ראו `deploy/fail2ban-lemontank.conf` (שכבת הגנה שנייה מעל השרת) |
| 2FA למנהל | `/account/security` — מומלץ בחום |

| עדכונים | `apt upgrade` + `npm audit` פעם בשבוע |
| ניטור | `/admin/security` — בדיקה שבועית של "התוקפנים הבולטים" |

## 9. מה המערכת **לא** עושה (ביושר)

* **התקפת נפח (DDoS)** — לא נפתרת בשרת בודד. הפתרון: Cloudflare / ספק עם Scrubbing.
* **TLS fingerprinting** — זיהוי Burp לפי חתימת TLS (JA3) דורש טרמינל TLS משלנו;
  אין את זה מול reverse proxy. לכן אנחנו מזהים לפי כותרות והתנהגות.
* **בוטים מבוזרים** — חסימה לפי IP פחות אפקטיבית מול רשת של אלפי כתובות;
  שם נכנסים ניקוד, מונים וקצב, אבל ה-WAF של ה-CDN חזק יותר.
* **התקפה ממוקדת של תוקף אנושי עם ידע** — אין הגנה מוחלטת; יש עומק, זיהוי ומינימום נזק.
* **משתמשים לגיטימיים מאחורי VPN** — עלולים להיחסם אם מפעילים `block-all`.

## 10. פרטיות

* כתובות IP נשמרות בלוג האבטחה לצורך זיהוי תוקפים. אפשר לשמור **האש** בלבד:
  `node scripts/security.mjs set ip_mode hash` (הפאנל יציג מזהים מגובבים).
* ניקוי אוטומטי לפי `retention_days` (ברירת מחדל 90 יום) —
  `node scripts/security.mjs purge 90`.
* סיסמאות: scrypt (N=2^15), טוקנים נשמרים כ-SHA-256 בלבד, סודות 2FA ב-AES-256-GCM.
