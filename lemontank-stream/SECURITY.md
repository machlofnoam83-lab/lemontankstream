# 🛡️ אבטחת LemonTank Stream

> המסמך הזה מתאר את שכבת האבטחה של המערכת: מה היא עושה, איך מנהלים אותה,
> ואיפה הגבולות שלה. הקובץ הזה הוא גם ה"חוזה" — מה שכתוב כאן אמור להתאים לקוד.

---

## 1. הרעיון: דלת אחת בלבד

```
        האינטרנט
            │
            ▼
   ┌──────────────────────────────────────────────┐
   │  server.mjs — שער האבטחה (פורט 3000)         │
   │  • ניקוי כותרות וזיהוי IP אמיתי              │
   │  • זיהוי תקיפות (SQLi/XSS/RCE/traversal…)    │
   │  • חסימת כלי יירוט (Burp/ZAP), סורקים, TOR   │
   │  • מלכודות, הגבלת קצב, חסימת IP אוטומטית     │
   └──────────────────────────────────────────────┘
            │  (רק בקשות נקיות, עם חתימת HMAC)
            ▼
   ┌──────────────────────────────────────────────┐
   │  Next.js — בתוך אותו תהליך                    │
   │  • אימות הרשאות (RBAC) בכל נקודת קצה          │
   │  • Zod על כל קלט · parameter binding בכל SQL  │
   │  • CSRF, CSP עם nonce, סשנים חתומים           │
   │  • סריקת גוף הבקשה + חסימת IP גם כאן          │
   └──────────────────────────────────────────────┘
            │
            ▼
      SQLite (WAL) — קובץ מקומי, לא חשוף לאינטרנט
```

**למה זה חשוב:** אין פורט נוסף שאליו אפשר לפנות ישירות. גם אם מישהו ינסה
`http://server:3311` — אין מה לפנות אליו. כל בקשה, דף, API או קובץ מדיה עוברת בשער.

## 2. מה נחסם, ומתי

| מה זוהה | דוגמה | תגובה |
|---|---|---|
| הזרקת SQL | `?q=1 UNION SELECT password FROM users` | 🚫 חסימה + **חסימת IP ל-2 שעות** |
| הרצת פקודות | `;cat /etc/passwd`, `${jndi:ldap://…}` | 🚫 חסימה + **12 שעות** |
| חדירת נתיבים | `../../../../etc/passwd` | 🚫 חסימה + **6 שעות** |
| XSS | `<script>`, `onerror=`, `javascript:` | 🚫 חסימה + **שעה** |
| כלי יירוט | כותרת `Proxy-Connection`, חתימת Burp/ZAP | 🚫 חסימה + **3 שעות** |
| סורקי פגיעויות | `sqlmap`, `nikto`, `nuclei`, `gobuster` | 🚫 חסימה + **3 שעות** |
| נתיבי מלכודת | `/.env`, `/wp-login.php`, `/phpmyadmin`, `/.git` | 🚫 חסימה + **24 שעות** |
| סריקת נתיבים | 40 בקשות ל-404 בחמש דקות | 🚫 חסימה + **12 שעות** |
| כוח גס | 20 כשלי התחברות ב-15 דקות | 🚫 חסימה + **שעה** |
| הברחת בקשות | `Content-Length` + `Transfer-Encoding` יחד | 🚫 חסימה + **שעה** |
| הצפה | מעל 600 בקשות בדקה | 429, ואחרי 3 חריגות — **חסימה** |
| זיוף Host / כותרות IP | `X-Originating-IP`, Host לא מורשה | 🚫 חסימה או ניקוד |

**החמרה אוטומטית:** כל חזרה של אותה כתובת **מכפילה** את זמן החסימה (עד 30 יום).

**מה לא נחסם סתם:** גלישה רגילה, חיפוש בעברית, גרש בתקציר ("rock'n'roll"),
משתמשים מאחורי VPN (ברירת מחדל: ניקוד בלבד — ראו §6),
וכתובות פנימיות (localhost/LAN) שלעולם לא נחסמות — כדי שלא תנעל את עצמך בחוץ.

## 3. איך לא נועלים את עצמך בחוץ

1. **פטור פנימי** — כתובות `127.0.0.1`, `10.x`, `192.168.x`, `172.16-31.x` לא נחסמות לעולם
   (אפשר לכבות: `node scripts/security.mjs set internal_bypass off`).
2. **חסינות אנשי צוות** — בקשה עם סשן של מנהל/עורך לא נחסמת, גם אם יצאה מכתובת חסומה.
3. **שחרור מהטרמינל:**
   ```bash
   node scripts/security.mjs bans              # מי חסום ולמה
   node scripts/security.mjs unban 1.2.3.4     # שחרור כתובת
   node scripts/security.mjs unban --all       # מנעול חירום — משחרר הכול
   node scripts/security.mjs mode monitor      # מצב ניטור: לוגים בלי חסימות
   ```
4. **מצב ניטור** — לפני עלייה לאוויר אפשר להריץ שבוע ב-`monitor` ולראות
   מה היה נחסם, בלי לחסום בפועל.

## 6. מדיניות פרוקסי / VPN / TOR

| ערך | משמעות |
|---|---|
| `off` | לא לחסום — רק לתעד |
| `score` *(ברירת מחדל)* | ניקוד בלבד. פרוקסי אמיתי מתנהג כמו דפדפן ולכן לא נחסם, אבל כל סימן נוסף מצטבר |
| `block-writes` | גלישה מותרת, אבל התחברות/הרשמה/העלאה נחסמות (מומלץ אם יש ספאם) |
| `block-all` | חסימת כל תנועה מפרוקסי/ענן/TOR |

**TOR** חסום כברירת מחדל (`TOR_BAN=on`) — פנייה מיציאת TOR נחסמת ל-24 שעות.

**למה לא לחסום VPN כברירת מחדל?** כי גם לקוחות תמימים משתמשים ב-VPN,
וחיפוש שקט של כתובת שהיא "מרכז נתונים" עלול לחסום אנשים אמיתיים.
מעבירים ל-`block-writes` או `block-all` בשורה אחת — מהפאנל או מהטרמינל:
`node scripts/security.mjs set proxy_policy block-all`.

## 8.5 סבב 3 — שכבת "המבצר" (הגנת עומק לחשבון ולסשן)

השכבה הזו עונה על שאלה אחת: **מה קורה אחרי שמישהו כבר השיג סיסמה?**
כל מה שכאן מבוסס על ההנחה שהסיסמה תיפגע מתישהו — ולכן ההגנה עוברת לסשן,
למכשיר ולפעולה.

### 8.5.1 אימות דו-שלבי (2FA) — חובה לכל חשבון צוות

* **סיסמה נכונה לא יוצרת סשן** אם לחשבון מופעל 2FA — מוחזר "אתגר" בלבד
  (`POST /api/auth/login` → `{requires2fa:true, challenge}`). הקוד נשלח
  בשלב שני עם האתגר; בלי קוד נכון אין עוגיית סשן בכלל.
* אתגר 2FA תקף **5 דקות ופעם אחת**, ונשמר כ-Hash.
* מדיניות `require_staff_2fa` (ברירת מחדל `on`): כל חשבון `editor`/`admin`/`owner`
  חייב 2FA כדי לגעת באזור הניהול. הבדיקה העצמית מסמנת סגל בלי 2FA כ**כשל**.
* 8 קודי גיבוי חד-פעמיים לכל חשבון.

### 8.5.2 קישור הסשן למכשיר ולרשת

לכל סשן נשמרת טביעת דפדפן (Hash של User-Agent) ורשת (`/24` ל-IPv4, `/64` ל-IPv6),
בנוסף ל**פקיעה מוחלטת** (`absolute_expires_at`) שלא מתארכת לעולם.

* עוגייה שנגנבה ומשמשת **מדפדפן אחר** → הסשן מבוטל מיד, נרשם אירוע
  `session_device_changed` בדרגת critical, והמשתמש צריך להתחבר מחדש. גם
  התוקף וגם הקורבן מאבדים את הסשן — זה נכון: סשן חשוד לא ממשיך לחיות.
* מעבר לרשת אחרת (למשל מ-Wi-Fi לסלולרי) **לא** מנתק — הוא מסמן סיכון,
  ומצריך אימות מחדש לפעולות רגישות.
* פקיעת חוסר-פעילות: 45 דקות לסגל, 14 יום למשתמש רגיל (sliding), עם תקרה מוחלטת.

### 8.5.3 אימות מחדש (step-up) לפני פעולה הרסנית

פעולות בלתי הפיכות דורשות את הסיסמה **שוב**, בתוך חלון של 15 דקות:

`user.delete` · `user.role_change` · `settings.update` · `security.settings_update` ·
`api_key.create` · `api_key.revoke` · `title.delete` · `admin.export` ·
`admin.backup` · `admin.restore` · `payment.refund` · `admin.impersonate`

מימוש: `POST /api/security/step-up` עם הסיסמה → חלון חתום ב-DB. בלי חלון —
`403 STEP_UP_REQUIRED` עם שם הפעולה. **משמעות מעשית:** גניבת עוגיית סשן
לא מספיקה כדי למחוק משתמשים או להוציא מפתח API.

### 8.5.4 יומן ביקורת משורשר (tamper-evident)

כל רשומת ביקורת נושאת `seq`, `prev_hash` ו-`entry_hash` (SHA-256 משורשר).
שינוי/מחיקה של רשומה בעבר שוברים את השרשרת — וזה מזוהה בשתי דרכים:
`GET /api/admin/fortress` (מחזיר `auditChain`), ו-`node scripts/fortress-check.mjs`
שמאמת באופן עצמאי (לא דרך הקוד של האפליקציה).

```bash
node scripts/fortress-check.mjs --tamper   # מוכיח שהגלאי עובד: מזייף העתק ומזהה
node scripts/audit-repair.mjs --check      # מצב השרשרת (מדפיס חריגות לפי seq)
```

**תיקון מכוון ולא חשאי:** אם השרשרת נשברת מסיבה לגיטימית (עריכה ידנית של
המסד, שחזור חלקי), `scripts/audit-repair.mjs --resign --from <seq> --yes`
מחתים מחדש מ-seq נתון בלבד, מדפיס כל רשומה שמשתנה, ורושם אירוע
`audit_resign` בדרגת **critical**. כלומר: אפשר לתקן, אבל אי אפשר לתקן בשקט.

### 8.5.5 רשימת היתר לכתובות ניהול + שחזור מנעילה

`admin_ip_allowlist` (נקבע ל-`/api/admin/fortress` או מהסקריפט) מגביל את אזור
הניהול לכתובות מוכרות (תומך ב-CIDR ובתחיליות).

```bash
node scripts/allowlist.mjs --show
node scripts/allowlist.mjs --set "203.0.113.7,198.51.100.0/24" --yes
node scripts/allowlist.mjs --clear --yes     # המסלול היחיד אחרי נעילה עצמית
```

שינויים מהשרת נרשמים ב-`security_events` (עם סימון offline) — ולא נכתבים
ליד ליד השרשרת, כדי ששרשרת הביקורת תיווצר תמיד על ידי היישום בלבד.

### 8.5.6 מדיניות סיסמאות ובדיקת דליפות

שתי בדיקות שפועלות **בצד השרת** (לא רק בטופס):

1. **מבנה + הקשר** — 10 תווים לפחות, ספרה ותו מיוחד, בלי חזרות ורצפים
   (1234/qwerty/abcd), בלי קשר לאימייל, לשם או לשם האתר, ובלי סיסמאות
   מהרשימה הנפוצה (כולל קיצורי תווים: `P@ssw0rd#2027` מזוהה כ-`password`).
2. **דליפה בפועל** — מול Have I Been Pwned בשיטת **k-anonymity**: נשלחים
   5 תווים ראשונים של ה-SHA-1, והסיסמה עצמה לא עוזבת את השרת (וגם לא
   נשמרת). תוצאות נשמרות במטמון 7 ימים (`breach_checks`).
   מצב: `security_settings.breach_check` = `enforce` (ברירת מחדל) · `warn` · `off`.
   **בלי אינטרנט** הבדיקה המרוחקת מדולגת בשקט — הרשימה המקומית ממשיכה לעבוד.

`POST /api/auth/password-check` (30 בדקות) מזין את מדד החוזק החי בהרשמה
ובאיפוס סיסמה — הסיסמה נבדקת בזיכרון ונזרקת, בלי רישום ביומן.

### 8.5.7 מיסוך פרטים מזהים (PII)

* יומן הביקורת וזיהוי חשבונות כושלים נכתבים עם אימייל **ממוסך** (`n**m@g****.com`).
* דוח המבצר מציג את חברי הצוות ממוסכים (`maskedStaff`); הכתובת המלאה נשארת במסד.
* לוח האבטחה של עורך מציג אימיילים ו-IP ממוסכים; `admin`/`owner` רואים מלא
  (הם גם אלו שמטפלים בפניות). `stats.piiMasked` מסמן מה מוצג ממוסך.
* תגובת יצירת מפתח API לא מחזירה יותר את ה-Hash של המפתח.

### 8.5.8 גיבוי מוצפן + שחזור מאומת

```bash
node scripts/backup-encrypted.mjs                      # יצירה + אימות מיידי
node scripts/backup-encrypted.mjs --list               # רשימת גיבויים
node scripts/backup-encrypted.mjs --restore <f> --to <path>
node scripts/backup-encrypted.mjs --prune --keep 7     # שמירת 7 אחרונים
```

* זורק `VACUUM INTO` (עותק עקבי גם כשהאתר חי), דוחס (gzip), ומצפין
  **AES-256-GCM** עם מפתח שנגזר מ-`BACKUP_KEY` (או `APP_SECRET`).
  חתימה `LTBK1` + manifest עם SHA-256.
* **כל גיבוי מאומת מיד**: פענוח, פתיחת SQLite, `PRAGMA integrity_check`
  וספירת טבלאות. גיבוי שלא אומת — לא נחשב גיבוי.
* אזהרה מפורשת כשמשתמשים במפתח נגזר במקום `BACKUP_KEY` ייעודי.

### 8.5.9 הגבלת קצב שמדויקת לשימוש אמיתי

* **התחברות**: 30 בקשות ל-5 דקות לכל IP (מספיק למשפחה שלמה מאחורי NAT,
  כולל השלמת 2FA שהיא בקשה נוספת לכל התחברות).
* **כשלי התחברות בלבד**: 8 ל-5 דקות לאותו IP — הדלי שמונע brute-force.
  התחברות מוצלחת **לא** שורפת מכסה, כך שאין חסימה עצמית של משתמשים.
* בנוסף: נעילת חשבון מדורגת (`failed_logins` → `locked_until`) לפי מספר
  הניסיונות הכושלים של החשבון עצמו.

### 8.5.10 כלי התפעול של השכבה

|---|---|
| `scripts/fortress-check.mjs [--verbose] [--tamper]` | בדיקת חוסן עצמית: סודות, הגירות, שלמות השרשרת, 2FA לסגל, קישור סשנים, רשימת היתר, הרשאות קובץ. `--tamper` מוכיח שהגלאי מזהה זיוף. |
| `scripts/audit-repair.mjs --check \| --resign --from <seq> --yes` | אבחון השרשרת ותיקון מוצהר (נרשם כאירוע critical). |
| `scripts/allowlist.mjs --show \| --set … \| --clear` | ניהול רשימת ההיתר של הניהול, כולל מסלול שחזור מנעילה. |
| `scripts/backup-encrypted.mjs` | גיבוי מוצפן, רשימה, שחזור מאומת, ניקוי ישנים. |
| `scripts/reset-2fa.mjs --status \| --email … \| --staff` | איפוס 2FA של חשבון (מכשיר אבוד) — רק עם גישה לקבצי השרת. |
| `scripts/test-prep.mjs` | מאפס מכסות וחסימות לפני הרצת בדיקות (`npm test` מריץ אותו אוטומטית). |

### 8.5.11 מה שהשכבה הזו **לא** נותנת — ביושר

* **PSP אמיתי / PCI-DSS / 3-D Secure** — אין סליקה. כל "תשלום" במערכת הוא
  רשומת מנוי בלבד; אין כרטיסים, אין סליקה, אין מה לתקוף במובן הזה.
* **ביקורת חיצונית (pen-test) ואישורים** — לא קיימים. אפשר להזמין, זה כסף וזמן.
* **SIEM / SOC 24-7** — יש זיהוי והתראות בתוך המערכת, אין מוקד אנושי.
* **WAF של CDN / HSM / WORM** — לא קיים ברמת שרת בודד; יומן הביקורת
  tamper-evident אבל יושב באותו דיסק.
* **"בלתי נראה"** — מצב חמקן מקטין טביעות אצבע; הוא לא הופך אתר לבלתי ניתן
  לאיתור. מי שמחפש מספיק — ימצא. מה שכן אפשר: למצוא **מאוחר**, ולהיות מוכן.

## 9. מה המערכת **לא** עושה (ביושר)

* **התקפת נפח (DDoS)** — לא נפתרת בשרת בודד. הפתרון: Cloudflare / ספק עם Scrubbing.
* **TLS fingerprinting** — זיהוי Burp לפי חתימת TLS (JA3) דורש טרמינל TLS משלנו;
  אין את זה מול reverse proxy. לכן אנחנו מזהים לפי כותרות והתנהגות.
* **בוטים מבוזרים** — חסימה לפי IP פחות אפקטיבית מול רשת של אלפי כתובות;
  שם נכנסים ניקוד, מונים וקצב, אבל ה-WAF של ה-CDN חזק יותר.
* **התקפה ממוקדת של תוקף אנושי עם ידע** — אין הגנה מוחלטת; יש עומק, זיהוי ומינימום נזק.
* **משתמשים לגיטימיים מאחורי VPN** — עלולים להיחסם אם מפעילים `block-all`.

## 10. פרטיות

* כתובות IP נשמרות בלוג האבטחה לצורך זיהוי תוקפים. אפשר לשמור **האש** בלבד:
  `node scripts/security.mjs set ip_mode hash` (הפאנל יציג מזהים מגובבים).
* ניקוי אוטומטי לפי `retention_days` (ברירת מחדל 90 יום) —
  `node scripts/security.mjs purge 90`.
* סיסמאות: scrypt (N=2^15), טוקנים נשמרים כ-SHA-256 בלבד, סודות 2FA ב-AES-256-GCM.
* בדיקת דליפות סיסמה שולחת **5 תווים של Hash** בלבד (k-anonymity) — הסיסמה
  עצמה לא נשלחת לשום מקום ולא נשמרת. אפשר לכבות: `breach_check=off`.
* יומני האבטחה נכתבים עם אימייל ממוסך; רשומות ביקורת מלאות נשארות במסד בלבד.
