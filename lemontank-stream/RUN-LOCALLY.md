# 🖥️ הרצת האתר במחשב שלך

> 👉 **רוצה צעד-אחר-צעד עם מה שצריך להופיע בכל שלב?** → **[START-HERE.md](./START-HERE.md)**
> (ווינדוס, כולל מה לעשות כש-Node חסר ומה הפלט הנכון בכל פקודה)

האתר הזה הוא **תוכנה שרצה אצלך** — לא אתר שמישהו אחר מארח. כלומר: המחשב שלך הוא
השרת, כתובת האתר היא `http://localhost:3000`, והתוכן יושב בקובץ SQLite אחד
(`data/lemontank.db`) שאף אחד חוץ ממך לא נוגע בו.

**זמן התקנה:** כ-5 דקות בפעם הראשונה. אחרי זה — קליק כפול אחד.

---

> 🔴 **האתר חי רק כשהחלון פתוח.** `http://localhost:3000` הוא לא אתר באינטרנט —
> הוא *המחשב שלך*. אם סגרת את החלון (או שהמחשב נכבה) הדפדפן יראה
> "לא ניתן להתחבר". לבדיקה מהירה: **`npm run status`**.

## 🚀 הדרך הקצרה (3 שלבים)

### שלב 1 — להתקין Node.js (פעם אחת בחיים)
היכנס ל-**https://nodejs.org** והורד את הכפתור הגדול שכתוב עליו **LTS**.
התקן עם "Next" עד הסוף (אין מה לשנות).

> למה זה צריך את זה? Node.js מריץ גם את השרת וגם את מסד הנתונים המובנה
> (`node:sqlite`) — ולכן אין צורך ב-MySQL, ב-Docker או בהתקנות נוספות.
> **צריך גרסה 22.13 ומעלה** — כל גרסת LTS עדכנית עומדת בזה.
> אחרי ההתקנה **סגור ופתח מחדש** חלונות טרמינל, אחרת הוא לא ימצא את node.

### שלב 2 — להוריד את הקוד
- **אם יש לך Git:** `git clone https://github.com/machlofnoam83-lab/lemontankstream.git`
- **אם אין:** נכנסים לריפו ב-GitHub → כפתור ירוק **Code** → **Download ZIP** →
  מחלצים לתיקייה (למשל `C:\lemontank`).

### שלב 3 — קליק כפול
| מערכת | מה ללחוץ |
|---|---|
| **Windows** | `START-HERE-WINDOWS.cmd` (קליק כפול) |
| **macOS** | `START-HERE-MAC.command` (קליק ימני → **Open** בפעם הראשונה) |

הקובץ מדליק הכל לבד: מתקין חבילות, מייצר סודות, יוצר מסד, בונה את האתר,
פותח את הדפדפן ב-`http://localhost:3000`, ומשאיר את האתר רץ.

**לעצירה:** `Ctrl + C` בחלון שנשאר פתוח.

## 🔑 כניסה לאתר

> 📌 **הכתובת לגלישה היא `http://localhost:3000`.** אם ראית בהודעת השרת כתובת
> עם `0.0.0.0` — זו הגדרת *האזנה* פנימית ("קבל חיבורים מכל כרטיס רשת"), והדפדפן
> יציג `ERR_ADDRESS_INVALID`. המקום היחיד ששם `0.0.0.0` מופיע אצלך הוא פלט השרת —
> פשוט התעלם ממנו והשתמש ב-localhost (או בכתובת ה-IP שמוצגת ליד "מהטלפון").

| | |
|---|---|
| כתובת | `http://localhost:3000` |
| דוא"ל מנהל | `admin@lemontank.local` |
| סיסמה | `ChangeMe-Admin-2026!` |
| הוספת תוכן | `http://localhost:3000/admin/titles/new` |

הקטלוג מגיע **ריק** — בדיוק כמו שביקשת: אתה ורק אתה מוסיף סרטים, סדרות ופרקים
דרך פאנל הניהול. רוצה קודם לראות איך זה נראה עם תוכן לדוגמה?

```bash
node scripts/seed.mjs --reset --demo     # מוסיף תוכן לדוגמה
node scripts/clear-content.mjs           # מוחק אותו בחזרה
```

> ⚠️ הסיסמה הזו היא סיסמת **פיתוח מקומי** וקבועה בכוונה כדי שיהיה קל להיכנס.
> לפני שאתה פותח את האתר לאינטרנט — החלף אותה ב-`/account/security` והפעל 2FA.

## 🛠️ הדרך הידנית (טרמינל)

אם מעדיפים פקודות, או שהקובץ הדו-קליקי לא רץ:

```bash
cd lemontank-stream
npm ci                     # התקנת חבילות
npm run setup              # הכנה מלאה: סודות + מסד + בנייה (בטוח להרצה חוזרת)
npm run start              # הרצה  →  http://localhost:3000
```

שימושי לדעת:

| פקודה | מה היא עושה |
|---|---|
| `npm run doctor` | **הבדיקה החזקה:** מרים את השרת בפועל, בודק IPv4/IPv6/localhost, ומציג את השגיאה האמיתית אם יש |
| `npm run doctor -- --report` | אותו דבר + כותב `lemontank-report.txt` לשליחה |
| `npm run status` | **האתר רץ?** אומר אם כן — ואיפה; אם לא — מה להריץ (התשובה ל"לא ניתן להתחבר") |
| `npm run setup` | הכנה אוטומטית — משלים רק את מה שחסר |
| `npm run setup:check` | בדיקה בלבד — **לא** משנה כלום |
| `npm run port` | איזה פורט פנוי כרגע (3000 תפוס? ימצא אחר) |
| `npm run recover` | עדכון גרסה + השלמת מה שחסר (מקבילה ל-`recover-dev.sh`, עובד בווינדוס) |
| `npm run dev` | מצב פיתוח עם רענון חי (מתאים לשינויים בקוד) |
| `npm run start` | מצב רגיל (דורש בנייה — `npm run build`) |
| `node scripts/local-setup.mjs --demo` | הכנה + תוכן לדוגמה |
| `npm run db:status` | מצב הסכימה — אילו הגירות הוחלו |
| `npm run db:migrate` | השלמת הגירות סכימה (בדרך כלל אוטומטי) |
| `npm run security:status` | מצב שכבת האבטחה והחסימות |
| `node scripts/giftcard.mjs create` | הנפקת גיפט קארד |

> ⚠️ **בווינדוס אין `bash`** — פקודות כמו `bash scripts/recover-dev.sh` לא יעבדו ב-cmd
> או ב-PowerShell. המקבילה: **`npm run recover`** (אותו דבר בדיוק, בלי bash).
> קבצי `.sh` בפרויקט מיועדים ללינוקס/מק/שרת.

## 📱 לפתוח למשפחה/חברים באותה רשת Wi-Fi

1. מצא את כתובת ה-IP של המחשב:
   - **Windows:** `ipconfig` → שורה `IPv4 Address` (למשל `192.168.1.20`)
   - **macOS:** `ipconfig getifaddr en0`
2. כולם פותחים בדפדפן: `http://192.168.1.20:3000`
3. אם ווינדוס שואל על פיירוול בהרצה הראשונה → **Allow** (רשת פרטית).

> 🔒 זה עובד ב-**HTTP לא מוצפן** — מתאים רק לרשת ביתית מהימנה. **אל תפתח פורט
> לאינטרנט ככה.** להעלאה אמיתית יש מסמך נפרד: [`FREE-HOSTING.md`](FREE-HOSTING.md)
> (שרת חינם + דומיין חינם + HTTPS), ו-[`DEPLOY.md`](DEPLOY.md) לפריסה מלאה.

## 🔄 עדכון גרסה (בלי לאבד תוכן)

התוכן שלך חי ב-`data/lemontank.db` — הוא **לא** חלק מהקוד ולכן עדכון לא נוגע בו.

```bash
cd lemontank-stream
node scripts/backup-encrypted.mjs   # גיבוי לפני כל עדכון (מומלץ)
npm run recover                     # מוריד את הקוד החדש + משלים מה שחסר, בלי לגעת במסד
npm run start
```

גיבוי לפני עדכון הוא לא סיסמה באוויר: **הוא גם מחזיר גיבויים ישנים.** אם מפתח
הגיבוי השתנה (`BACKUP_KEY`) — `--restore` ינסה אוטומטית את כל המפתחות הקיימים
בסביבה ויגיד לך באיזה מהם הקובץ נפתח, במקום להיכשל בפענוח סתום.

> 💡 **הסודות שלך לא נדרסים.** `npm run setup` / `npm run recover` משלימים רק מה
> שחסר: `BACKUP_KEY` מתווסף אם אין, אבל **אף פעם לא מוחלף** (החלפה הייתה הופכת
> גיבויים קודמים לבלתי-פתיחים), וסיסמת המנהל נקבעת רק בהתקנה חדשה לגמרי — במחשב
> שכבר יש בו מסד, שום ערך שלך לא נגע.

בזיפ שהורד מחדש: מחלץ לתיקייה חדשה, **מעתיק לשם את `data/`** מהתיקייה הישנה
(ואת `.env.local` אם יש), ומריץ את הלאנצ'ר.

## 🩺 תקלות נפוצות

| מה קורה | הסיבה | הפתרון |
|---|---|---|
| **"לא ניתן להתחבר" / `ERR_CONNECTION_REFUSED`** | **אין שרת שרץ** (הכי שכיח) — `localhost` נענה רק כשהאתר רץ באותו מחשב, וסגירת החלון מפילה אותו. סיבה שנייה: הדפדפן ניסה IPv6 והשרת האזין ל-IPv4 בלבד | `npm run doctor` — מרים את השרת בפועל ובודק את כל הדרכים (תוקן: השרת מאזין כעת גם ל-IPv4 וגם ל-IPv6). להעלאה: `npm run start` |
| **`ERR_ADDRESS_INVALID` על `0.0.0.0:3000`** | `0.0.0.0` = "האזן מכל כרטיס רשת" — **לא כתובת לגלישה** | גש ל-`http://localhost:3000`. השרת כבר מדפיס את הכתובת הנכונה |
| הפורט 3000 תפוס (אתר אחר/הרצה קודמת) | הלאנצ'ר בוחר פורט פנוי אוטומטית | או ידנית: `set PORT=3001 && npm run start` — ואז `http://localhost:3001` |
| `נדרש Node.js 22.13 ומעלה` | גרסה ישנה מותקנת | התקן LTS מ-nodejs.org, **פתח חלון חדש** |
| `'node' is not recognized` | Node לא מותקן / הטרמינל לא נטען מחדש | התקן LTS → סגור ופתח טרמינל |
| `EADDRINUSE` / הפורט תפוס | כבר רץ אתר על 3000 | סגור את החלון הישן, או `set PORT=3001 && npm run start` (ווינדוס) / `PORT=3001 npm run start` |
| עברית מוצגת כג'יבריש ב-cmd | קידוד המסוף | הלאנצ'ר מטפל בזה (`chcp 65001`); בטרמינל ידני: `chcp 65001` |
| ווינדוס חוסם את ה-`.cmd` | SmartScreen על קובץ מהאינטרנט | קליק ימני → Properties → **Unblock** → או "Run anyway" |
| macOS: "cannot be opened" | Gatekeeper | קליק ימני על הקובץ → **Open** → Open |
| `npm ci` נכשל | אין אינטרנט / פרוקסי | בדוק חיבור; מאחורי פרוקסי: `npm config set proxy …` |
| הדף לא נפתח לבד | הדפדפן לא נפתח אוטומטית | פשוט פתח `http://localhost:3000` ידנית |
| `CSRF` / עוגייה לא נשמרת | כתובת לא תואמת | השתמש ב-`http://localhost:3000` בדיוק (לא IP) |
| מסד נעול / מושחת | שני שרתים רצים על אותו קובץ | סגור את כל החלונות והרץ אחד בלבד |
| רוצה להתחיל נקי | מסד מבולגן | `node scripts/seed.mjs --reset` (מוחק הכל) |
| `no such table: …` בסקריפט | המסד נוצר ולא הועלה עדיין | `npm run db:migrate` (מעודכן: קורה אוטומטית בהתקנה ובבדיקות) |
| גיבוי ישן לא נפתח | מפתח הגיבוי הוחלף | שחזור מנסה כל מפתח שבסביבה ומדווח מה עבד — ראה למטה |

## ❓ שאלות מהירות

**זה בטוח?** כן, מבחינת הלוגיקה: כל בקשה עוברת דרך שכבת אבטחה (`server.mjs`) —
זיהוי תקיפות, מלכודות, הגבלת קצב, חסימת כלי סריקה, בלי כותרות שמסגירות את הטכנולוגיה.
פירוט: [`SECURITY.md`](SECURITY.md) · מצב חמקן: [`STEALTH.md`](STEALTH.md).

**למה האתר לא "עולה לאינטרנט" מעצמו?** כי `localhost` הוא המחשב שלך בלבד — וזה
הכוונה: שום מידע לא יוצא החוצה. כשתחליט לחבר דומיין — [`FREE-HOSTING.md`](FREE-HOSTING.md).

**מה נשרף לי בדיסק?** בערך 300–500MB (חבילות + בנייה). המסד עצמו קטן — מגהבייטים בודדים.

**אפשר להריץ במקביל לאתר אחר?** כן, פשוט על פורט אחר: `PORT=3001 npm run start`.
